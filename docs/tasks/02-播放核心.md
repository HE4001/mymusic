# B：播放核心与本机状态（sol xhigh）

## 目标与写入范围

实现 src/hooks/usePlayer.ts、src/lib/api.ts、preferences.ts、queue.ts、demo.ts 及有必要的少量 tests/player*.test.ts / queue*.test.ts / preferences*.test.ts。遵守 src/types.ts 的 PlayerController。不要写 UI/后端/工程配置。

## 必须完成

1. 唯一 HTMLAudioElement，crossOrigin anonymous 在 src 前设置，metadata 预载，只播放当前曲目，effect 清理支持 StrictMode。
2. selectTrack(track, queue): 点击当前曲目按设计 toggle，其他曲目重建队列快照；playQueued(id) 用原队列切歌；自然结束按 mode，手动 next 不受单曲循环影响；shuffle 未访问集合一轮结束停止、previous 历史栈、>3秒 previous 回开头。
3. 每次新播放操作递增标识并 AbortController 取消旧签名；每个 await 和媒体恢复处理确认当前操作。异步期间用户 pause 必须生效；旧播放 Promise/错误不能覆盖新状态。
4. 签名在内存，只保留当前票据。续播或 seek 临近到期(<60秒)时更新，metadata 后恢复位置和播放意图；自动更新每次最多一次；buffering 不等于过期；用户暂停不得被恢复任务自动启动。
5. play Promise 区分 NotAllowedError（提示点击继续）、旧 AbortError（忽略）和真实错误；不假装取得媒体 HTTP 状态。加载失败展示可重试错误，不无限跳歌。
6. localStorage cloud-music:v1：收藏、最近 id、position、mode、volume；读取校验/异常保护，曲库加载后剔除不存在 id；5秒最多写一次，暂停/pagehide 补存；刷新后暂停、不请求音频。空加载数组不能提前擦掉已保存数据，考虑 usePlayer 先拿空数组后真实加载场景。
7. api helper 原生 fetch 同源、signal、Content-Type/status/结构基本校验，遇 Access HTML/重定向给认证错误；不把任何网络错误包装成登录错误。
8. demo.ts 提供 3 首明确为演示音频的 Track，按需生成短 WAV Blob（自己合成简单音调），仅开发模式使用；销毁时 revoke URL；不访问外部音乐，也不混入生产 B2 清单。导出 demoLibrary；与 getPlayTicket 的分支只存在 DEV && options.demo。

## 接口

遵循 00 文件以及 src/types.ts。favorites 用 string[]，controller.error 为 string|null，notice 为 string|null。所有公开操作可以 void 或 Promise<void>（类型约定为 void 也可返回 Promise但须内部捕获）。currentTrack 无曲库时 null。canSeek 来自真实媒体时长与载入状态。

## 有限验证

只针对竞争/暂停恢复、队列末尾、持久化安全等真实风险增加少量 Vitest 测试；可将音频控制抽出一个小 controller 以便假 audio 验证，但不做大框架或完整浏览器 mock。主代理将统一 npm test/check/build。完成报告实际文件、关键取舍和未验证浏览器行为。
