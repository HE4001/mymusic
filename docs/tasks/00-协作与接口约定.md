## 全体约束

直接修改分配范围的文件，完成后报告实际改动、检查、已知限制。共享工作区多人并行，不删除或覆盖他人改动。不修改 package.json、共享类型或其他代理模块；若接口不够使用，向主代理提出具体变更。不要提交 Git、不要部署云端、不要创建 Sites 项目、不要自行启动其他代理。

用户指定 Vite/React + Cloudflare Pages + B2 的小型项目，保留此技术方案，不用 Sites 托管/ChatGPT 登录模板替代。不要引入数据库、音频代理、密码系统、复杂 UI 框架。主代理管理依赖与最终构建；子代理只做有限且有意义的验证，不重复跑全套检查。

没有真实音频或密钥时，不伪装成连接成功。生产清单默认为空。开发可使用显式选择的演示模式，由客户端提供本地生成的音频测试 fixture，界面明确“演示曲库”；演示不能成为生产鉴权失败后的自动 fallback。

## 共享契约

`src/types.ts` 由主代理拥有，是前端/后端共享纯类型，无运行时数据。

- Track: id/title/artist/album/mimeType 字符串、duration 为 number|null。
- Library: schemaVersion:1、updatedAt:string、tracks:Track[]。
- PlayTicket: trackId:string、url:string、expiresAt:number（Unix 毫秒）。
- PlaybackMode: sequence|shuffle|repeat-one。
- PlaybackStatus: idle|loading|playing|paused|buffering|error。
- usePlayer(tracks: Track[], options?: PlayerOptions): PlayerController；PlayerOptions 为 {demo?:boolean,libraryLoaded?:boolean}。UI 仅在成功取得真实/演示曲库后将 libraryLoaded 设 true，区分加载中空数组与真实空库，避免误清理本机收藏。
- Controller 字段和方法以 src/types.ts 为准。队列存 id；收藏由 controller 管理并持久化；UI 不直接写 localStorage。
- api.ts 导出 getLibrary(signal?:AbortSignal):Promise<Library>、getPlayTicket(id:string,signal?:AbortSignal):Promise<PlayTicket>，以及可识别 code 的 ApiError。
- 演示仅 `import.meta.env.DEV && URLSearchParams(location.search).get('demo')==='1'` 启用；hooks 使用 options.demo 再和 DEV 双重确认。库失败默认显示错误，不自动进入演示。
- UI 可导入 src/lib/demo.ts 的 demoLibrary 作为开发数据；生产路径不允许演示播放。
- API GET /api/library 返回 Library；GET /api/play-url?id=... 返回 PlayTicket。全部 API 错误 `{error:{code,message}}`，no-store。
- server/library.ts 导出 validateLibrary(value:unknown)（抛出可读错误并返回规范清单），getLibrary()（安全公开字段），findTrack(id)。主代理用 `tsx scripts/validate-library.ts` 调用相同校验，避免两套规则。

## 主代理的关键审查

检查真实音频单实例、播放竞争/暂停意图、签名过期有限恢复、Range 不被签死；检查 Access JWT 完整验证、无配置关闭访问、URL 路径编码；检查产物不泄露服务端清单或凭据；构建前后端，少量风险测试。外部 B2/Cloudflare 实际验证若缺凭据必须列为未验证，不冒充已上线。
