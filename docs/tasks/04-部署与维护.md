# D：部署配置与维护说明（luna max）

## 目标

用简洁、准确的文件把本项目交给用户配置 B2/Cloudflare Pages，不实施云端操作。依据根设计指南第 10～12 节和 docs/tasks/00 的约定。

## 独占文件

README.md、docs/DEPLOY.md、wrangler.jsonc、.dev.vars.example、public/_headers、public/_routes.json、b2-cors.example.json。

## 具体要求

1. README 中文：项目用途、npm install/dev/check/test/build/preview:pages、开发 ?demo=1 演示明确无真实 B2、生产需要配置、如何编辑 server/library.json。提供设计与任务文档的相对链接。
2. DEPLOY：Pages Project 创建和 dist 构建、根 functions 随 Wrangler 部署；7个配置字段；生产/预览独立；Access 覆盖正式/默认/预览域名；JWT 后端仍验证；B2 CORS 合并而非破坏其他应用；限定只读密钥；真实音频手工验收（播放/Range206/短TTL过期）和边界。
3. wrangler.jsonc name cloud-music、pages_build_output_dir ./dist、compatibility_date 2026-09-07；不填真实密钥、不加 Workers main，不加 KV/D1/R2/Sites。
4. .dev.vars.example 只有占位，B2_ENDPOINT/REGION/BUCKET/KEY_ID/APPLICATION_KEY、ACCESS_TEAM_DOMAIN/AUD；若提到可选 TTL，注明需服务端支持及合法范围，避免擅自定义。
5. _routes.json 仅 /api/*；_headers Referrer-Policy no-referrer 和 nosniff；b2-cors.example.json 用正确 S3 CORS 格式/生产占位域名/GET HEAD/Range/exposed range headers。
6. 不写认证绕过，不要求用户向聊天贴密钥，不宣称自动走 Cloudflare 音频CDN/免费流量。不标记没执行的部署或验收为成功。

## 验收与编码指南

JSON 可解析，路径/脚本与项目契约相符，命令使用 Pages 而非普通 Worker deploy；不需要测试框架或压力测试。你只负责文档和配置，不修改 package.json，主代理会同步实际脚本并审查。最终报告改动文件和必须由用户填写的信息。
