# iOS Safari 后台播放计划与验收标准

基线：master `5c49ef7`。需求：系统播放控件正确显示歌曲，改善切后台续播，适配系统灵动岛播放展示。保持 Pages + 私有 B2 + 密码入口，不增加原生应用、数据库或后台服务。

## 已确认的问题与边界

- 播放器未使用 Media Session，没有主动向系统提交标题、歌手、专辑、播放状态及控制回调。
- AuthGate 在 focus/pageshow 校验遇到临时网络错误时会撤销本地已登录状态，卸载播放器，可能中断原本可继续播放的音频。
- pagehide 当前只保存进度，并未主动暂停；不要把它误判为已证实的断播原因。其余断播原因须按网络、音频事件、签名与系统回收分别定位。
- 目标是实际音频播放期间减少应用自身造成的中断，并正确恢复界面。网页不能保证 Safari 进程不被 iOS 回收。禁止靠静音循环、定时网络请求、忙循环、Wake Lock 或 Service Worker 宣称永久保活。
- 灵动岛由 iOS 决定是否展示系统正在播放。网页提交标准媒体信息和响应媒体按键；不以 CSS 模拟灵动岛，不承诺 ActivityKit 原生活动界面。系统未显示的字段必须区分“API已提交”与“真机已展示”。
- 当前曲库没有封面字段。第一阶段不把通用图案当作专辑封面，也不新增后台封面下载系统；无封面不等于无媒体信息。

## 实施顺序

1. 接入 Media Session：功能检测；更新歌曲元数据、真实播放状态、合法时长/进度；API不支持或某个动作拒绝注册时继续正常播放。
2. 注册系统播放、暂停、上一首、下一首及支持的拖动/快进快退。复用原控制器，避免独立播放器或重复播放队列。
3. 保持同一 Audio 实例和触摸事件内同步 play 的路径。切后台不重建音频、不清 src；回到前台按实际音频状态更新，已暂停不自动恢复。
4. 处理会话检查：初次访问继续关闭未授权访问；已经登录时网络暂时失败不立即卸载播放器；明确会话失效、成功退出仍停止播放器和清理系统信息。
5. 集成并运行相关类型检查、关键测试和一次构建。桌面移动视口只验布局，模拟 Media Session 只验API行为。
6. 在用户实际 iPhone/iOS/Safari 场景做下面的人工验收，再判断后台和灵动岛支持是否通过。无设备时标记“待真机验证”。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| M1 | 播放、切歌 | 提交当前曲目的标题、歌手、专辑；系统可显示的位置不残留上一首信息；不显示签名URL或密钥 |
| M2 | 系统播放控制 | 系统暂停、继续、上一首、下一首各执行一次；不重复切歌，不把暂停动作当作toggle导致误播 |
| M3 | 系统进度 | 有效时长加载后提交准确进度；NaN/Infinity/越界不传给系统；支持拖动的设备中控制有效 |
| B1 | 切其他应用5分钟 | 网络正常且系统未终止页面时持续播放；返回后曲目、进度、播放状态与实际音频一致 |
| B2 | 锁屏30分钟 | 连续队列跨过至少两次切歌，记录是否连续、控件信息是否更新；注明设备/iOS、网络和省电模式，不能用单首长音频代替切歌验证 |
| B3 | 暂停后切后台再返回 | 保持暂停，不因focus/pageshow、会话检查或恢复签名而自动播放 |
| B4 | 网络波动/音频中断 | 临时会话请求失败不卸载已登录播放器；无缓存且断网时不要求继续出声；恢复后可操作，不循环重试；电话/其他媒体中断后不擅自抢播 |
| A1 | 会话失效/退出 | 初次未登录不加载曲库；明确失效重新登录；成功退出停止音频、解绑系统控制并清除元数据；已签发B2链接仍受原有效期约束 |
| D1 | 支持灵动岛的iPhone | 实际播放时检查系统Now Playing及长按展开，确认曲目信息和支持的控制正确；系统是否展示、显示哪些字段单独记录，网页测试不能替代 |
| R1 | 回归 | 切歌竞态、暂停意图、刷新后不自动播放、无Media Session的浏览器、StrictMode卸载不重复绑定均正常 |
| S1 | 安全与资源 | 没有密码/B2密钥进入前端、日志或提交；无静音音轨、保活轮询、新权限请求或持续高频任务 |

## 测试范围与证据

只添加能验证实际风险的少量测试：元数据/动作/清理，生命周期不误播放，认证网络错误与明确失效的区别。已有测试通过后不做无目的重复或大规模设备矩阵。

人工记录至少包含：提交号、iPhone型号、iOS版本、Safari标签页或主屏入口、网络类型、省电模式、具体操作、观察结果。5分钟和30分钟是本项目验收窗口，不是平台续播保证。未实测的单元格不得填写“通过”。
